## 一、先理解 agent 的基本結構

一個簡單的 agent 通常包含這 5 個部分：

### 1. 目標（Goal）
agent 要完成什麼？
例如：
- 幫使用者查天氣
- 幫忙整理資料
- 幫忙回答問題
- 幫忙下指令自動化工作

### 2. 狀態（State / Memory）
agent 要記住什麼？
例如：
- 使用者剛剛說了什麼
- 已經做過哪些步驟
- 工具有沒有失敗

### 3. 決策邏輯（Planner / Policy）
agent 怎麼決定下一步？
例如：
- 如果使用者問天氣，就呼叫天氣工具
- 如果資料不足，就先問清楚
- 如果失敗，就重試或換方法

### 4. 工具（Tools）
agent 可以使用哪些功能？
例如：
- 查資料
- 搜尋網頁
- 呼叫 API
- 讀寫檔案
- 操作資料庫

### 5. 回饋迴圈（Loop）
agent 不是只做一次就結束，而是：
> 思考 → 行動 → 看結果 → 再思考 → 再行動

這就是 agent 跟一般函式最大的差別。

---

## 二、最小可行的 agent 長什麼樣子

你可以把它想成這種流程：

```text
使用者輸入
    ↓
agent 分析需求
    ↓
選擇工具
    ↓
執行工具
    ↓
取得結果
    ↓
整理回答
```

## 三、簡單 Python 範例概念

下面是一個很簡化的 agent 思路：

```python
def agent(user_input):
    if "天氣" in user_input:
        return get_weather("Taipei")
    elif "時間" in user_input:
        return get_current_time()
    else:
        return "我還不會處理這個任務"
```

這種寫法很簡單，但它已經有 agent 的雛形：  
**根據輸入決定行動，再回傳結果。**

## 七、寫 agent 的實作步驟

### Step 1：定義任務
先想清楚：
- agent 要幫誰？
- 要做什麼？
- 成功標準是什麼？

### Step 2：列出可用工具
例如：
- `get_weather(city)`
- `search_web(query)`
- `save_note(text)`

### Step 3：設計決策規則
例如：
- 如果問題包含「天氣」→ 用天氣工具
- 如果問題包含「時間」→ 用時間工具
- 如果資訊不足 → 先問澄清問題

### Step 4：加入記憶
例如：
- 紀錄使用者偏好
- 紀錄目前對話狀態
- 紀錄已完成的步驟

### Step 5：加入失敗處理
例如：
- 工具失敗就重試
- 如果資料缺少就要求補充
- 如果無法完成就回報原因

## 八、最容易犯的錯

### 1. 一開始做太大
不要一開始就做「萬能 agent」。  
先做一個小而清楚的功能。

### 2. 沒有工具邊界
agent 不是什麼都能做。  
要明確知道：
- 什麼能做
- 什麼不能做
- 什麼要先問使用者

### 3. 沒有停止條件
agent 不能無限循環。  
一定要設定：
- 最多執行幾輪
- 什麼情況算完成
- 什麼情況算失敗
